# Protocol test vectors

Generated by `npm run vectors` from `scripts/generate-vectors.ts`. Every implementation
(TypeScript, Swift, Kotlin) runs these in its own test suite so a message signed on one
platform verifies on every other.

| File | What it pins down |
|---|---|
| `test-keys.json` | Three P-256 private keys as JWK. TEST ONLY. Created once, then reused so device ids stay stable. |
| `identity.json` | Public key encoding, device id derivation, fingerprint display, and invalid keys that must be rejected. |
| `signing-input.json` | The exact bytes an envelope signature covers, plus their SHA-256. |
| `envelopes.json` | Receiver rule cases, processed in order by one receiver with a fixed clock and trust set. |
| `pairing.json` | HMAC-SHA256 pairing proof. Deterministic. |
| `server-auth.json` | Signature a device presents to the rendezvous server, with negative cases. |
| `turn.json` | coturn `use-auth-secret` credentials. Deterministic. |

ECDSA signatures are randomized. Regenerating changes the signature bytes but nothing they sign.
Implementations verify signatures against the public key; they never compare signature bytes.
